# DeepBlue Rescue — Capa de Persistencia

> Proyecto práctico de persistencia para organizaciones dedicadas al rescate, rehabilitación y monitoreo de fauna marina. Construido con **Java 21**, **Spring Boot 4**, **Spring Data JPA**, **Hibernate**, **Flyway**, **PostgreSQL** y **Testcontainers**.

---

## 1. Arquitectura y Tecnologías

```text
               Modelo de Dominio (Java 21)
                          │
                          ▼
            Spring Data JPA (Repositories)
                          │
                          ▼
             Hibernate (JPA Implementation)
                          │
                          ▼
           PostgreSQL (Base de Datos Relacional)
                          ▲
                          │
             Flyway (Gestión de Migraciones)
```

- **Java 21 (LTS)**: Lenguaje principal con records, text blocks y pattern matching.
- **Spring Boot 4.1.x**: Framework base para inversión de control y configuración.
- **Spring Data JPA**: Capa de abstracción de repositorios y Query Methods.
- **Hibernate ORM**: Motor de mapeo objeto-relacional (ORM) con validación estricta de esquema (`ddl-auto: validate`).
- **Flyway**: Herramienta de migración y versionado determinista de base de datos.
- **PostgreSQL**: Motor de base de datos relacional para producción y pruebas.
- **Testcontainers & Docker**: Infraestructura automatizada de pruebas de integración sobre instancias reales de PostgreSQL.

## 2. Modelo de Dominio y Relacional

### Diagrama de Relaciones

```text
RescueCenter (1) ───< (N) RescueCase (1) ─── (1) Animal (1) ─── (1) MedicalRecord
                                                   │
                                                   │ (1)
                                                   ▼
                                                  (N)
                                               Treatment
                                                  (N)
                                                   ▲
                                                   │ (1)
                                                   │
                                               Specialist (N) ───< (M) >─── (M) Expertise
                                                    (specialist_expertise)
```

### Entidades y Reglas de Mapeo
1. **`RescueCenter`**: Representa sedes de rescate (`code` único, nombre, ciudad). Relación $1:N$ con `RescueCase`.
2. **`RescueCase`**: Expediente del rescate (`caseCode` único, fecha, ubicación, `status`). Relación $1:1$ bidireccional con `Animal`.
3. **`Animal`**: Fauna marina rescatada (`animalCode` único, nombre común, nombre científico, sexo, `trackingDeviceCode` opcional único). Relación $1:1$ con `MedicalRecord` y $1:N$ con `Treatment`. Propietario de la FK hacia `RescueCase`.
4. **`MedicalRecord`**: Evaluación clínica inicial (`initialWeight`, condición, lesiones, observaciones). Propietario de la FK hacia `Animal`.
5. **`Specialist`**: Médicos veterinarios y biólogos (`professionalCode`, nombre, email, estado activo). Propietario de la relación $N:M$ con `Expertise`.
6. **`Expertise`**: Catálogo de especialidades marinas (`name` único).
7. **`Treatment`**: Procedimientos médicos aplicados (`performedAt`, `type`, `description`). Claves foráneas hacia `Animal` y `Specialist`.

## 3. Estrategia de Migraciones con Flyway

El esquema relacional no es generado por Hibernate; es creado y versionado exclusivamente por **Flyway**:

1. **`V1__create_schema.sql`**:
   - Creación de las 7 tablas del dominio y la tabla asociativa `specialist_expertise`.
   - Claves primarias con `GENERATED BY DEFAULT AS IDENTITY`.
   - Claves foráneas con restricciones referenciales y reglas de unicidad (`UNIQUE`) para modelar relaciones $1:1$ (`animals.rescue_case_id`, `medical_records.animal_id`).
   - Restricción `CHECK` sobre `rescue_cases.status` para validar los 6 estados del ciclo de vida.
   - Creación de índices en claves foráneas y columnas de filtro frecuente (`rescue_date`, `status`, `performed_at`).
2. **`V2__insert_expertise_catalog.sql`**:
   - Inserción de especialidades iniciales del catálogo: *Marine Reptiles*, *Marine Mammals*, *Marine Birds*, *Trauma*, *Rehabilitation*, *Toxicology*.
3. **`V3__add_tracking_device_to_animal.sql`**:
   - Evolución del esquema: incorporación de la columna `tracking_device_code VARCHAR(50) UNIQUE` para rastreo GPS sin modificar migraciones previas.

## 4. Consultas del Dominio (Spring Data JPA y JPQL)

| Necesidad de Negocio | Mecanismo | Implementación |
|---|---|---|
| Buscar centro/animal/caso por ID | **Método heredado** | `findById(id)` |
| Guardar y sincronizar inmediatamente | **Método heredado** | `saveAndFlush(entity)` |
| Buscar caso por código único | **Query Method** | `findByCaseCode(String caseCode)` |
| Casos por estado ordenados por fecha | **Query Method** | `findByStatusOrderByRescueDateAsc(RescueStatus status)` |
| Animales de un centro (navegación profunda) | **Query Method** | `findByRescueCaseRescueCenterCode(String code)` |
| Búsqueda de animales por nombre parcial | **Query Method** | `findByCommonNameContainingIgnoreCase(String text)` |
| Especialistas activos por especialidad | **`@Query` + JPQL** | `findActiveByExpertise(@Param("expertiseName") String expertiseName)` |
| Historial de tratamientos de un animal | **Query Method** | `findByAnimalIdOrderByPerformedAtAsc(Long animalId)` |
| Tratamientos en intervalo de fechas | **`@Query` + JPQL** | `findTreatmentsBetweenDates(LocalDateTime start, LocalDateTime end)` |
| Tratamientos por centro de rescate | **`@Query` + JPQL** | `findByRescueCenterCode(String centerCode)` |
| Tratamientos por especialidad médica | **`@Query` + JPQL** | `findBySpecialistExpertise(String expertiseName)` |
| **Reto sin guía:** Animales en rehabilitación con tratamiento de especialista en Trauma | **`@Query` + JPQL** | `findAnimalsInStatusWithSpecialistExpertise(RescueStatus status, String expertiseName)` |

## 5. Conceptos Fundamentales Evaluados

### ¿Qué diferencia existe entre JPA, Hibernate, Spring Data JPA y PostgreSQL?
- **JPA (Jakarta Persistence API):** Especificación estándar de Java (interfaces y anotaciones como `@Entity`, `@Id`, `@OneToMany`) que define cómo debe funcionar el ORM.
- **Hibernate:** Implementación concreta del estándar JPA. Traduce las operaciones de entidades y consultas JPQL a sentencias SQL nativas.
- **Spring Data JPA:** Capa sobre Hibernate que elimina la necesidad de escribir implementaciones DAO mediante la interfaz `JpaRepository` y Query Methods automáticos.
- **PostgreSQL:** Sistema gestor de base de datos relacional (RDBMS) donde residen físicamente las tablas, índices, datos y restricciones.

### ¿Por qué `ddl-auto: validate` y no `ddl-auto: update`?
- En entornos profesionales, **Flyway es el único componente autorizado a modificar la base de datos**.
- Con `validate`, Hibernate se limita a verificar en el arranque que las entidades Java coincidan estrictamente con las tablas existentes en PostgreSQL. Si hay discrepancias de nombres o tipos, la aplicación se detiene de inmediato evitando estados inconsistentes o pérdida de datos.

### ¿Qué significa `mappedBy` y cómo identificar al propietario?
- `mappedBy` se coloca en el **lado inverso** (no propietario) de la relación bidireccional e indica el nombre del atributo en la entidad destino que gestiona la relación.
- El **lado propietario** es aquel que contiene la clave foránea física (`@JoinColumn` en 1:1 y N:1, o `@JoinTable` en N:M). Solo las modificaciones en el lado propietario son traducidas a sentencias SQL de persistencia.

## 6. Ejecución de Pruebas de Integración

Las pruebas se ejecutan contra un contenedor efímero de **PostgreSQL** levantado automáticamente mediante **Testcontainers**.

### Requisito previo:
Tener **Docker Desktop** iniciado en tu equipo.

### Comando de ejecución:
```bash
./mvnw clean test
```
o en Windows PowerShell:
```powershell
.\mvnw.cmd test
```
